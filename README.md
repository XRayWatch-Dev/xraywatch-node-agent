Официальный агент узла для [XRayWatch](https://xray.watch). Он устанавливается
на сервер с VPN-подключениями и позволяет XRayWatch отдельно проверять:

- доступность самого сервера по TCP и UDP;
- доступность привязанных к нему VPN-адресов и конечных точек;
- доставку результатов проверки в панель XRayWatch.

Один агент может обслуживать несколько адресов и VPN-эндпоинтов на одном
сервере. Агент не читает VPN-конфигурации, не управляет VPN-клиентами и не
получает доступ к Docker Socket.

## Проект XRayWatch

XRayWatch — сервис мониторинга VPN-инфраструктуры и доступности подключений.
Панель проекта: [xray.watch](https://xray.watch).

> Репозиторий готовится к первой публичной версии. До публикации релиза образ
> `ghcr.io/xraywatch-dev/xraywatch-node-agent` может быть недоступен.

## Как это работает

```text
                             HTTPS + HMAC
┌──────────────────┐  heartbeat / наблюдения  ┌────────────────────┐
│ XRayWatch        │ ◄──────────────────────── │ Node Agent         │
│ control API      │ ────────────────────────► │ на VPN-сервере     │
└────────┬─────────┘        регистрация        └─────────▲──────────┘
         │                                                │
         │ задание + подписанный Ed25519 ticket           │ TCP / UDP
         ▼                                                │ :18443
┌──────────────────┐                                      │
│ XRayWatch Checker│ ─────────────────────────────────────┘
│ из другой сети   │     проверка публичного адреса узла
└──────────────────┘
```

1. В панели XRayWatch создаётся узел, для которого выдаются одноразовый токен,
   адрес control API и публичный Ed25519-ключ доверия.
2. Во время регистрации агент обменивает одноразовый токен на собственные
   `node_id` и секрет.
3. Удалённый XRayWatch Checker получает задание и подписанные tickets, после
   чего проверяет публичный адрес узла по TCP и UDP.
4. Агент слушает один и тот же порт по TCP и UDP. Каждый запрос принимается
   только с короткоживущим подписанным ticket для конкретного узла, протокола,
   запуска и допустимого размера ответа.
5. Каждые 30 секунд агент отправляет heartbeat и накопленные наблюдения в
   control API. Запросы подписываются HMAC с timestamp и уникальным nonce.
6. Если control API временно недоступен, до 512 последних наблюдений остаются
   в локальной очереди и отправляются после восстановления связи.

## Быстрый старт

### Требования

- Linux `amd64` или `arm64`;
- Docker Engine и Docker Compose v2;
- исходящий HTTPS-доступ к control API XRayWatch;
- открытый в firewall TCP- и UDP-порт, по умолчанию `18443`.

### 1. Получение команды в XRayWatch

В панели [xray.watch](https://xray.watch) откройте раздел **Агенты** и нажмите
**Добавить агент**. Выбирать профиль, вводить IP или перечислять VPN-порты не
нужно: панель сразу покажет:

- готовую команду установки — адрес control API и `XRAYWATCH_TRUST_KEY` уже
  будут подставлены в неё;
- одноразовый токен регистрации, который установщик запросит отдельно.

Самостоятельно генерировать ключ доверия или токен не требуется. Пустое значение
в `.env.example` — это только место для значения, выданного панелью. После
первого подключения XRayWatch определит IP агента и свяжет его с доменами этого
сервера в загруженных маршрутах.

### 2. Настройка firewall

Откройте выбранный порт для входящих подключений по TCP и UDP. Установщик
намеренно не меняет настройки firewall.

Например, для Ubuntu с UFW и стандартного порта:

```sh
ufw allow 18443
```

### 3. Установка

Выполните на VPS команду из панели. Она загрузит репозиторий в
`/opt/xraywatch-agent`, подставит выданные XRayWatch настройки и запустит
установщик.

Когда установщик запросит токен, вставьте одноразовый токен из панели. Токен не
попадёт в `.env`, переменные окружения или аргументы процесса. После регистрации
агент запустится в фоне с политикой перезапуска `unless-stopped`.

### Ручная установка

Этот вариант нужен только если готовую команду из панели нельзя использовать.

Сначала скопируйте проект:

```sh
git clone https://github.com/XRayWatch-Dev/xraywatch-node-agent.git /opt/xraywatch-agent && cd /opt/xraywatch-agent && cp .env.example .env && nano .env
```

Затем перенесите в `.env` адрес control API и ключ доверия, показанные панелью:

```dotenv
XRAYWATCH_CONTROL_URL=https://control.example.com
XRAYWATCH_TRUST_KEY=BASE64_ED25519_PUBLIC_KEY
XRAYWATCH_LISTEN_PORT=18443
XRAYWATCH_VERSION=latest
XRAYWATCH_STATE_VOLUME=xraywatch-node-agent-state
```

Одноразовый токен регистрации и секрет узла в `.env` не добавляются.

Запустите установщик:

```sh
/opt/xraywatch-agent/install.sh
```

Скрипт проверит конфигурацию, загрузит образ и запросит одноразовый токен из
панели в интерактивном режиме.

## Настройка

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | :---: | --- | --- |
| `XRAYWATCH_CONTROL_URL` | да | — | HTTPS-адрес control API |
| `XRAYWATCH_TRUST_KEY` | да | — | Публичный Ed25519-ключ в Base64 для проверки probe tickets |
| `XRAYWATCH_LISTEN_PORT` | нет | `18443` | Порт, который агент слушает одновременно по TCP и UDP |
| `XRAYWATCH_VERSION` | нет | `latest` | Тег контейнерного образа; для production лучше закрепить релизный тег |
| `XRAYWATCH_STATE_VOLUME` | нет | `xraywatch-node-agent-state` | Имя Docker volume с идентичностью и очередью наблюдений |

`XRAYWATCH_STATE_DIR` — внутренняя настройка контейнера. При обычной установке
её изменять не требуется.

### Что хранится на узле

В Docker volume находятся:

- `identity.json` — `node_id` и секрет узла, права файла `0600`;
- `observations.jsonl` — ограниченная очередь ещё не доставленных наблюдений.

Volume не входит в образ, исходный код и Git. При обычном обновлении он
сохраняется, но переносить или копировать его на другой сервер нельзя.

Одна запись занимает около 200 байт, поэтому очередь из 512 обычных наблюдений
занимает примерно 100 КиБ. Даже при максимально длинных допустимых полях файл
не превысит примерно 2 МиБ. Во время атомарного обновления рядом временно
хранятся старый и новый файлы, поэтому для очереди достаточно менее 5 МиБ
свободного места.

## Проверка работы

Состояние контейнера:

```sh
cd /opt/xraywatch-agent && docker compose ps
```

Последние логи:

```sh
cd /opt/xraywatch-agent && docker compose logs --tail=100
```

Версия агента:

```sh
cd /opt/xraywatch-agent && docker compose exec xraywatch-node-agent /xraywatch-node-agent --version
```

Ожидаемый успешный запуск содержит версию, `node_id` и порт прослушивания. После
этого узел должен появиться online в панели XRayWatch.

## Обновление и удаление

### Обновление

```sh
cd /opt/xraywatch-agent && git pull --ff-only && docker compose up -d
```

Для предсказуемого production-обновления в `.env` указывается конкретный
релизный тег, например `XRAYWATCH_VERSION=v0.1.0`, вместо `latest`.

### Остановка

```sh
cd /opt/xraywatch-agent && docker compose down
```

Эта команда сохраняет Docker volume и регистрацию узла.

### Полное удаление

Сначала отзовите узел в XRayWatch. Затем остановите контейнер и отдельно удалите
volume, только если сохранённая идентичность и очередь больше не нужны:

```sh
cd /opt/xraywatch-agent && docker compose down -v
```

Удаление volume необратимо: для повторного запуска потребуется новая регистрация.

## Безопасность

### Защита probe-порта

- Ticket подписывается Ed25519 и привязан к `node_id`, протоколу, запуску,
  endpoint и бюджету данных.
- Срок действия ticket не может превышать двух минут.
- Nonce нельзя использовать повторно; replay-кеш ограничен 1024 записями.
- TCP payload ограничен 256 КиБ, UDP — 256 байтами.
- UDP-ответ никогда не больше запроса, поэтому агент нельзя использовать как
  усилитель DDoS.
- TCP-соединение имеет deadline 10 секунд; одновременно обслуживается не более
  64 TCP-соединений.

### Изоляция контейнера

- непривилегированный пользователь `65532:65532`;
- read-only root filesystem;
- все Linux capabilities удалены;
- включён `no-new-privileges`;
- нет host mounts и доступа к Docker Socket;
- лимиты: `0.5 CPU`, `128 MiB` памяти, `128` процессов и `1024` файловых
  дескриптора.

Контейнер использует `network_mode: host`, чтобы проверки доходили именно до
сетевых адресов хоста. Это осознанная часть сетевой модели, а не требование привилегированного режима.

### Связь с control API

- В production разрешён только HTTPS. HTTP допускается исключительно для
  loopback-разработки.
- Redirect-ответы не выполняются автоматически.
- Ответ control API ограничен 1 МиБ, timeout запроса — 15 секунд.
- Heartbeat и наблюдения подписываются HMAC-SHA256 с timestamp и nonce.

О найденных уязвимостях сообщайте по правилам из [SECURITY.md](SECURITY.md), а не через публичный issue.

## Ограничения

- Агент не устанавливает, не настраивает и не перезапускает VPN.
- Агент не открывает порт в firewall автоматически.
- Автоматического обновления и отдельного scheduler нет.
- Поддерживаются только Linux `amd64` и `arm64`.
- Потеря или удаление state volume требует отзыва узла и новой регистрации.
- При переполнении локальной очереди сохраняются только 512 последних наблюдений.

## Сборка и тесты

Локальная проверка проекта:

```sh
cd /opt/xraywatch-agent && make check
```

Команда проверяет форматирование, запускает `go vet` и все тесты с race detector.

Сборка бинарного файла:

```sh
cd /opt/xraywatch-agent && make build && ./dist/xraywatch-node-agent --version
```

Сборка контейнера:

```sh
cd /opt/xraywatch-agent && docker build --build-arg VERSION="$(cat VERSION)" -t xraywatch-node-agent:local .
```

Релизный тег должен точно совпадать с `v` + содержимое файла `VERSION`.
GitHub Actions публикует checksums, Linux-бинарники для `amd64`/`arm64` и
multi-arch образ в GitHub Container Registry.

## Решение проблем

### `Missing .env`

Если конфигурация отсутствует, она создаётся из примера, после чего заполняются
обязательные значения:

```sh
cd /opt/xraywatch-agent && cp .env.example .env && nano .env
```

### `XRAYWATCH_CONTROL_URL is required` или `XRAYWATCH_TRUST_KEY is required`

Корректность `.env` проверяется командой:

```sh
cd /opt/xraywatch-agent && docker compose config
```

Команда не должна выводить ошибку об отсутствующей переменной.

### `control URL must use HTTPS`

Требуется HTTPS URL, полученный при создании узла в XRayWatch. Обычный HTTP
разрешён только для `localhost` и loopback-адресов во время разработки.

### `load identity: ...; run with --enroll`

Агент ещё не зарегистрирован либо его state volume потерян. Требуется запустить
`/opt/xraywatch-agent/install.sh` с новым одноразовым токеном. Идентичность
другого узла использовать нельзя.

### Узел offline после успешного запуска

1. Проверить логи: `cd /opt/xraywatch-agent && docker compose logs --tail=100`.
2. Проверить исходящий HTTPS-доступ к control API.
3. Проверить, что TCP и UDP используют один и тот же порт из `.env`.
4. Проверить, что выбранный TCP- и UDP-порт открыт в firewall.
5. Проверить, что узел не был отозван в XRayWatch.
