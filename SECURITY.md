# Политика безопасности

Безопасность XRayWatch Node Agent влияет на доступность серверов пользователей,
поэтому сообщения об уязвимостях нужно передавать приватно.

## Как сообщить об уязвимости

Используйте [Private vulnerability reporting](https://github.com/XRayWatch-Dev/xraywatch-node-agent/security/advisories/new)
в этом репозитории. Не создавайте публичный issue до выпуска исправления.

Если приватная форма GitHub ещё не включена, свяжитесь с командой XRayWatch
через официальный канал поддержки на [xray.watch](https://xray.watch) и не
передавайте секретные данные в публичной переписке.

## Что указать в отчёте

По возможности приложите:

- версию агента или commit, на котором воспроизводится проблема;
- дистрибутив Linux и архитектуру;
- необходимые сетевые условия и уровень доступа атакующего;
- пошаговое воспроизведение и минимальный proof of concept;
- ожидаемый эффект и фактическое влияние;
- безопасный способ связаться с вами для уточнений.

Неполные отчёты тоже принимаются. Не включайте в отчёт действующие токены
регистрации, секреты узлов, приватные ключи, VPN-ссылки или чужие данные. Если
для воспроизведения нужен секрет, сначала согласуйте безопасный канал передачи.

## Поддерживаемые версии

Исправления безопасности выпускаются для последней опубликованной версии.
Пользователям рекомендуется обновляться до актуального релиза и закреплять его
тег в `XRAYWATCH_IMAGE_TAG`.

## Компрометация узла

Если state volume, `identity.json` или секрет узла могли стать доступны третьим
лицам:

1. отзовите узел в панели XRayWatch;
2. остановите агент;
3. удалите скомпрометированный state volume;
4. создайте новую регистрацию и используйте новый одноразовый токен;
5. не восстанавливайте старый `identity.json` из резервной копии.

## Ответственное исследование

Проверяйте уязвимости только на собственной инфраструктуре и тестовых данных.
Не нарушайте работу чужих узлов, не изменяйте и не извлекайте чужие данные и
дайте команде разумное время на проверку и выпуск исправления перед публичным
раскрытием.
